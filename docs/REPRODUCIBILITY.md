# Reproducing EgoEngine

The [release validation record](validation/RELEASE.json) lists executed checks,
generated frame counts and environment-specific interruptions.

Run commands from the repository root in an editable checkout. The example data,
robot meshes and object assets are included; no original workstation or separate
legacy repository is required. The supported starting point is the
[prepared-input contract](INPUTS.md).

## Environments

| Profile | Platform | Python | Installation |
| --- | --- | --- | --- |
| Visual and export | macOS or Linux with OpenGL | 3.10 | `pip install -r requirements/visual-tested.txt` then `pip install --no-deps -e .` |
| Action optimization | Linux, NVIDIA CUDA | 3.12 | `pip install -r requirements/action-tested.txt` then `pip install -e .` |

Use separate virtual environments: the tested visual profile uses NumPy 1.26
and MuJoCo 3.5; the CUDA profile uses NumPy 2.4 and MuJoCo 3.6. A CUDA-enabled
PyTorch build compatible with the local driver is required by the action profile.
On headless Linux rendering hosts set `MUJOCO_GL=egl`; on desktop machines use
the default OpenGL backend. Rendering does not require CUDA.

## Visual and dataset reproduction

In the visual environment:

```bash
egoengine validate
python -m unittest discover -s tests -v
bash scripts/reproduce_cpu.sh
```

Validation loads both scene XML variants for all six examples, checks array
dimensions/finiteness, decodes input videos and advances short CPU simulations.
The reproduction script generates all three Aria visual datasets. Each
`outputs/<case>/dataset.hdf5` contains 93, 105 or 108 reference frames for
`mustard_1`, `mustard_2` or `mustard_3`, respectively.

`egoengine demo` regenerates RB-Y1 foreground and visibility masks using the
retained replay functions and authored materials. It composites the prepared
demonstrator-free background and exports reference EEF controls. It does not
train a policy. Visual robot commands and floating-wrist action states remain
separate arrays in the dataset.

For the additional Franka + unchanged XHand example:

```bash
bash scripts/reproduce_franka_visual.sh
python scripts/validate_robot_visual.py --output outputs/franka_xhand/validation.json
python scripts/build_robot_visual_media.py
```

The [robot guide](USE_MY_ROBOT.md) describes wrist mapping, configuration fields,
joint limits and output inspection. The included
[three-case report](validation/FRANKA_XHAND.json) checks all 306 frames, unchanged
hand commands/EEF labels, camera/object tracks, native materials and rendered FK.

## Action reproduction

In the CUDA environment:

```bash
egoengine doctor
python -m unittest discover -s action/tests -v
python scripts/gpu_smoke.py
egoengine action --case mustard_1
```

The smoke fixture uses five frames and relaxed thresholds to exercise APIs and
serialization. Full-case generation uses the normal 0.05 m / 1 rad object tracking
limits, 20-control-step chunks, two-chunk planning, eight MPC samples, two MPC
iterations and a shared 1500-iteration PPO limit. The last accepted policy and
optimizer continue between RL windows, each capped at 300 iterations.

A completed action run writes
`outputs/<case>/action/trajectory_mjwp_mixed.npz` and a JSON report. Inspect the
success flag and complete committed frame count; a failed prefix is not a usable
full demonstration. Pair a successful result with visual outputs using the
`egoengine export --trajectory ...` command in the root README. Policy checkpoints
and learning traces are generated by training and are not downloaded implicitly.

To run switching and the full-horizon RL baseline with the same recipe:

```bash
python scripts/benchmark_case.py --data-root examples/prepared \
  --runner-root . --case mustard_1 --mode switching --seed 0 \
  --output outputs/comparison/mustard_1_switching
python scripts/benchmark_case.py --data-root examples/prepared \
  --runner-root . --case mustard_1 --mode pure_rl --seed 0 \
  --output outputs/comparison/mustard_1_pure_rl
```

Repeat for additional cases and seeds. Each report includes input/source hashes
and independent post-step tracking checks. Pure RL trains one policy over the
complete uncropped demonstration, without intermediate chunk resets or MPC.
It can use the full 1500 iterations in its single window.

The retained RL logger defines `env_steps` as
`(iteration + 1) * num_envs * num_steps_per_env`. Preserve the original metric's
progress convention, denominator and exclusions. Additional physics-work counts
are diagnostics. The mixed-runner binding to the original Cost analysis remains
unverified, so automatic Cost rankings are disabled. No verified simulation-step
reduction is claimed by this release. See [MODE_SWITCHING.md](MODE_SWITCHING.md).

## Known limitations

- All three Aria cases have complete visual inputs. Their CPU demos export
  reference controls; CUDA training is a separate step.
- The three TACO examples have complete action inputs but lack prepared removed
  backgrounds. Their historical generated videos are labeled previews.
- TACO Cut's saved retarget produces an empty robot mask for all 210 frames;
  its original retarget/camera pairing needs correction before visual generation.
- RL has completed some Aria demonstrations in previous runs, but outcomes vary
  with sampling and GPU contact dynamics. Successful action generation for all
  three bundled TACO interactions has not been established. A fixed seed does
  not guarantee identical policies or mode sequences across environments.
- Real-robot execution, raw-video perception, background-removal model training
  and downstream policy distillation are outside the tested entry points.

## Source and media provenance

[UPSTREAMS.json](../UPSTREAMS.json) pins the imported repositories.
The [visual source manifest](upstream/ORIGINAL_VISUAL_PIPELINE.json) records
upstream and release hashes separately: release cleanup removes comments and
draft annotations without changing Python ASTs or XML elements. Robot geometry,
materials, camera updates and compositor settings retain the authored values.
The regression tests also compare compiled materials against their XML sources.

[media/manifest.json](media/manifest.json) records stage media sources, alignment
and hashes. The README overview is the paper's Figure 1 from the official project
website. Rebuild stage figures with `bash scripts/reproduce_rendering.sh`.
