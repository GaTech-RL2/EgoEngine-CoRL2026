# EgoEngine prepared examples

Six prepared reference cases. Perception and digital
twin reconstruction are already represented by the prepared input files.

| Dataset | Case | Action input | Visual files |
| --- | --- | --- | --- |
| TACO | Brush / brush / bowl — 20230927_027 | Scene, assets, kinematic trajectory | Historical generated and action videos; regeneration inputs incomplete |
| TACO | Cut / knife / plate — 20230926_040 | Scene, assets, kinematic trajectory | Historical generated and action videos; regeneration inputs incomplete |
| TACO | Scrape off / knife / plate — 20230926_034 | Scene, assets, kinematic trajectory | Historical generated and action videos; regeneration inputs incomplete |
| Aria | Mustard 1 | Scene, assets, kinematic trajectory | Foreground, visibility mask, removed background, generated result |
| Aria | Mustard 2 | Scene, assets, kinematic trajectory | Foreground, visibility mask, removed background, generated result |
| Aria | Mustard 3 | Scene, assets, kinematic trajectory | Foreground, visibility mask, removed background, generated result |

The three Aria cases are different demonstrations of the same task.
TACO covers three different interactions.

## Contents

- `processed/<dataset_name>/xhand/<embodiment>/<task>/` contains both scene XMLs,
  `task_info.json`, and `0/trajectory_kinematic.npz` in EgoEngine-MPC's layout.
- `assets/` contains shared robot and object meshes. XML paths are relative.
  Missing Mustard meshes were restored from the checked `robosuite/yc` commit.
- `visual_inputs/Aria/<episode>/` contains prepared foreground/mask/background
  videos, calibration, retarget/replay JSON, and existing visual outputs.
- `visual_inputs/TACO/<task>/` contains retarget/camera data, original RGB,
  and matching `historical_*.mp4` outputs recovered from the project website.
- `manifest.json` records sources and completeness; `VALIDATION.json` records
  model, array, video, and CPU checks.

The Aria compositor was also run on all three supplied foreground/mask/background
sets. It generated 93, 105, and 108 frames respectively, matching their action
reference lengths. Those `visual_regenerated.mp4` outputs are included. Historical
TACO composited outputs also match the corresponding reference frame counts;
the original RGB and display-only action videos have different sampling rates.

These are historical processed references. They were not regenerated by the
cleaned retargeting or optimizer. They serve as format and installation tests;
they do not establish reproduction of historical task success rates.

## CPU validation

With NumPy, OpenCV, and MuJoCo installed, run `python validate_examples.py`.
This loads both XML variants, checks finite arrays and model dimensions, decodes
every included video, and advances each scene for five CPU simulation steps.
It does not run full-trajectory optimization or check task success.

## Unified entry point

The examples are included in the merged repository. See the [root README](../../README.md)
for installation and exact stage commands:

```bash
egoengine validate
egoengine demo --case mustard_1
egoengine action --case mustard_1
egoengine render --case brush_brush_bowl_20230927_027
egoengine media --render-scenes
```

The CPU demo regenerates RB-Y1 foreground and its visibility mask, then composites
them onto the prepared demonstrator-free background. Adaptive
Replay → MPC → RL uses the CUDA environment and the paper's two-chunk plan / one-
chunk commit procedure. The HDF5 exporter joins EEF action states with independent
RB-Y1 visual replay through frame/timestamp checks.

TACO background inputs remain missing. Its retained photographic videos are
previews, while new reference-scene renders can be generated for inspection.
No historical optimization success rate is claimed by these fixtures.

## Original RB-Y1 replay check

The unified renderer directly replays the saved `retarget.json` robot joints,
object poses and camera. The three Aria cases and TACO Brush/Scrape have visible
RB-Y1 layers. The original Cut retarget is inconsistent with its camera: all 210
masks are empty. Its inputs are preserved and this limitation is recorded in the
manifest; use the historical preview until a valid original retarget is recovered.
This is separate from Cut's complete floating-wrist action inputs.
